# 界面国际化维护

ToyShop 的 React 界面支持简体中文（`zh-CN`）和英文（`en`）。中文是源语言及缺词回退语言。`i18next` 和 `react-i18next` 在每个面板内创建独立实例；两份 JSON 通过静态导入随宿主离线打包，不进行网络加载。

## 词条与调用

- 界面词条位于 `packages/ui-react/src/l10n/locales/zh-CN.json` 和 `en.json`。`messages.ts` 只导入资源并以中文资源的结构约束英文资源。
- React 自有文案使用语义 key 与类型化 selector，例如 `t(($) => $.common.close)`。有数量的文案保留基础 key 和 `_one`、`_other` 变体，调用基础 key 并传入 `count`。
- 领域包继续输出框架无关的中文展示文案；`translateMessage()` 在 React 边界转换已登记的静态及少量动态文案。不要让新增 React 组件直接以中文原文作为 key。
- 会展示给用户的错误使用 `translateError()`。已登记的静态文案显示具体译文；未登记的宿主错误按现有错误码显示本地化概述。原始异常留在控制台或显式诊断视图，不拼进普通界面。表单校验使用 `translateValidationError()`，英文未知中文提示回退到通用校验文案。
- 插入、复制和状态标签应将标点及语序写入完整词条，而非在 JSX 中拼接全角冒号。

新增词条时，同时修改两份 JSON；保持 key 路径及 `{{参数}}` 名称一致。若文案来自领域包，先确认其中文源串已进入资源或动态映射。`tests/react-state/l10n.test.tsx` 会检查 key、参数和源串冲突；新增用户可见的错误还应补一条英文错误路径测试。

## 语言来源

| 界面              | `auto` 语言来源                                                      |
| ----------------- | -------------------------------------------------------------------- |
| Illustrator CEP   | 宿主 `appUILocale`                                                   |
| Photoshop WebView | 宿主 `uxp.host.uiLocale`                                             |
| Figma             | 插件 UI 的 `navigator.languages`；当前 Figma 插件 API 无界面语言字段 |
| Playground        | 浏览器 `navigator.languages`                                         |

用户手选语言保存在 `localStorage['astmatrix.language']`。`zh-Hans` 映射到 `zh-CN`；`zh-Hant` 和其他不支持的宿主语言使用英文。Photoshop 外部链接确认框沿用相同的宿主语言解析规则。

Photoshop 原生 UXP 面板是**已弃用的中文兼容回退**，仅在 WebView 不可用或加载失败时使用。本轮不为它增加英文词条，也不移除回退。Windows 安装器继续维护独立的 Inno Setup `.iss` 双语词条。

## 验证

```sh
pnpm check
pnpm build:web --profile=web-playground
pnpm build:web --profile=cep11
pnpm build:figma
pnpm check:figma-bundle
```

这些检查验证静态资源、类型、词条一致性和离线构建；真实宿主中的语言与原生回退仍需人工验收。
